# План: дневник смен водителя

## Стек

- Python 3.12, FastAPI, Pydantic v2, SQLite через стандартный `sqlite3` (без ORM).
- pytest + FastAPI `TestClient`.
- Клиент: статические файлы `static/index.html`, `app.css`, `app.js` (без сборщика), их отдаёт тот же сервер.
- Зависимости: `pyproject.toml` + `uv.lock`.
- Запуск: `docker compose up --build` (образ `python:3.12-slim`), для разработки `uv run uvicorn app.main:app`, тесты `uv run pytest`.


## Настройки (переменные окружения)

| Имя | По умолчанию | Смысл |
|---|---|---|
| `DAY_TZ_OFFSET` | `+05:00` | пояс, в котором считается «день»; только смещение `±HH:MM`; неверное значение — сервер не стартует |
| `TRIPS_FILE` | `data/trips.json` | файл, загружаемый при старте |
| `DB_PATH` | `data/trips.db` | файл SQLite (в Docker — volume) |

## API

### `GET /api/days/{date}`

`date` = `YYYY-MM-DD` или `today` (сегодня в поясе `DAY_TZ_OFFSET`).

`200`:
```json
{"date": "2026-10-01",
 "summary": {"trips_count": 2, "revenue": 3900, "commission": 585, "net": 3315,
   "by_payment": {
     "cash": {"trips_count": 1, "revenue": 1500, "commission": 225, "net": 1275},
     "card": {"trips_count": 1, "revenue": 2400, "commission": 360, "net": 2040}}},
 "trips": [{"id": "t1", "start": "2026-10-01T08:10:00+05:00",
            "end": "2026-10-01T08:32:00+05:00",
            "amount": 2400, "payment": "card", "commission": 360}]}
```

- Поездки отсортированы по `start`, затем по `id`.
- Пустой день: `200`, нули, обе строки `by_payment`, `trips: []`.
- Неверная дата: `422`.

### `POST /api/trips`

Тело: одна поездка `{id, start, end, amount, payment, commission}`.

| Код | Когда | Тело |
|---|---|---|
| `201` | новая поездка | сохранённая поездка |
| `200` | тот же `id`, те же данные | уже сохранённая поездка |
| `409` | тот же `id`, другие данные | `{"detail": "trip t1 already exists with different data"}` |
| `422` | ошибка проверки или битый JSON | стандартный формат FastAPI, свои тексты для наших правил |

### `GET /`

Статическая страница клиента.

## Модель данных

```sql
CREATE TABLE trips (
  id         TEXT PRIMARY KEY,
  start_utc  TEXT NOT NULL,   -- ISO в UTC, всегда с микросекундами
  end_utc    TEXT NOT NULL,
  amount     INTEGER NOT NULL,
  payment    TEXT NOT NULL,   -- 'cash' | 'card'
  commission INTEGER NOT NULL
);
CREATE INDEX trips_start_utc ON trips(start_utc);
```

- Время хранится в UTC строкой одной длины (`2026-10-01T03:10:00.000000+00:00`), поэтому сортировка строк = сортировка моментов.
- День `D` = полуинтервал `[D 00:00, D+1 00:00)` в `DAY_TZ_OFFSET`, переведённый в UTC; выборка `start_utc >= a AND start_utc < b`.
- Ответ отдаёт время в `DAY_TZ_OFFSET`; исходное смещение клиента не хранится.

## Правила проверки поездки (всё → 422)

- Все поля обязательны, `null` запрещён, лишние поля запрещены.
- `id`: JSON-строка, 1–64 символа, без обрезки пробелов.
- `start`, `end`: строка ISO 8601 со смещением; без пояса и числа (timestamp) — отказ.
- `end > start` строго; верхнего предела длительности нет.
- `amount`, `commission`: только JSON-целое (не `2400.0`, не `"2400"`, не `true`), в пределах int64.
- `amount > 0`, `0 ≤ commission ≤ amount`.
- `payment`: ровно `"cash"` или `"card"`.

## Защита от дублей

- Уникальность обеспечивает `PRIMARY KEY (id)` в БД.
- Сохранение: `INSERT`; при `IntegrityError` читаем запись и сравниваем.
- Сравнение: `start`/`end` как моменты (нормализованный UTC), `amount`, `payment`, `commission`.
- Другой `id` с тем же содержимым — другая поездка.

## Загрузка файла

- При старте сервера читаем `TRIPS_FILE`; каждая запись проходит ту же модель и ту же функцию сохранения, что POST (без HTTP).
- Плохая запись или конфликт `id` пропускается; в лог итог: `added N, unchanged M, rejected K: <id> <причина>`.
- Нет файла, битый JSON или не массив: ошибка в лог, старт с пустой БД.
- Повторный старт дублей не создаёт.

## Клиент

- Сводка дня (всего + наличные/карта) и список поездок.
- Кнопки «← пред. день», «след. день →», поле выбора даты; дата в URL `/?date=YYYY-MM-DD`.
- Без `?date=` клиент запрашивает `/api/days/today`.
- Суммы — числа без валюты. Есть форма добавления поездки: ошибки API показываются у полей, 200 — «Уже сохранено, дубля нет», 409 — понятная ошибка у поля ID (изменено на этапе 3).

## Допущения (в README)

1. «День» считается по времени начала поездки в поясе `DAY_TZ_OFFSET` (по умолчанию `+05:00`, как в данных).
2. «На руки» = выручка − комиссия; разбивка cash/card показывает число поездок, выручку, комиссию и «на руки» по каждому способу.
3. Деньги — целые числа в единицах исходных данных, валюта не указывается.
4. `id` поездки задаёт клиент; повтор с тем же `id` и теми же данными идемпотентен.
5. Данные в `data/trips.json` сверх примера из задания выдуманы для демонстрации.

## Тесты

Сводка:
1. Пример из задания: 2 / 3900 / 585 / 3315; cash 1/1500/225/1275; card 1/2400/360/2040 (+ unit-тест `summary.py`).
2. Пустой день: `200`, нули, обе строки разбивки, `trips: []`.
3. Граница дня: 23:59 и 00:00 по `+05:00` в разных днях; поездка через полночь — в дне начала.
4. Поездка в `Z` попадает в день по `+05:00` и возвращается в `+05:00`.
5. Сортировка по `start` при вставке не по порядку.
6. `today` возвращает текущую дату в `DAY_TZ_OFFSET`.

Дубли (результат проверяем через `GET /api/days/{date}`, не через БД):
7. Повтор того же тела: `201`, затем `200`, в дне одна поездка.
8. Тот же момент в другом смещении: `200`, не `409`.
9. Тот же `id`, другая сумма: `409`, в дне прежняя сумма.
10. Двойная загрузка файла не создаёт дублей.

Ветку `IntegrityError` отдельно не тестируем: сохранение всегда начинается с `INSERT`, поэтому каждый повтор в тестах 7–9 проходит через неё.

Seams (границы тестов):
- `summarize(trips)` в `app/summary.py` — unit;
- HTTP через `TestClient`; приложение собирает `create_app(settings=None, now=None)`, тест передаёт свои `Settings` (временная БД) и фиксированные часы `now`; `app/main.py` содержит `app = create_app()`;
- загрузка файла — через старт приложения с временным `trips_file`, проверка через `GET` и строку итога в логе.

Проверка данных (параметризованно, всё `422`): `amount` 0 и отрицательный, `end == start`, `end < start`, `payment="Cash"`, `commission > amount`, `commission < 0`, время без пояса, `amount` = `2400.0` / `"2400"` / `true`, лишнее поле, нет поля, `null`, битый JSON, неверная дата в URL.

Загрузка файла: плохая запись пропускается, хорошие сохраняются.
